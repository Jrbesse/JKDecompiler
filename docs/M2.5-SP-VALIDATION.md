## What this means

**Convert passes on all three SP maps. The stage-1 → stage-2 light fit does NOT
validate on the single-player maps with stage-1 grid seeds** — the same failure
mode academy1 has (kept=0, stageA = ambient-only), with two additional, SP-specific
reasons:

1. **Over-production**: stage-1 produces 263 (t1_sour) and 363 (t2_rancor)
   seeds vs academy1's 46 — each seed costs ~2min/light, so the full fit on any
   SP map is a multi-hour operation.
2. **vjun1 is unrecoverable by stage 1 at all** (grid/lightarray mismatch; the
   engine disables dynamic grid lighting).

The working acceptance path for the fit — **external lightmap-derived seeds**
via `--seeds <path>` (the academy1-measured 103.02 → 73.25 run) — was not
re-run here: deriving lightmap-derived seeds for the SP maps requires the
`mkseeds` analysis chain (dense original-driven points, empirical q3map2
falloff, per-face bright-mask clustering), which is academy1-specific and
material-costly. It is the follow-up for the working fit on SP maps.

## 2026-11-27 — Stage-1 quality gate (issue #22)

Implemented a seed-quality gate in stage 1 (`recover-lights`) and verified on
all three SP maps at branch `feat/stage1-seed-quality-gate`:

- `LightRecovery` now orders accepted seeds best-first by the same metric
  stage 2 uses (level consistency ascending, then forward-ray fraction
  descending, then evidence size descending) and accepts an optional
  `--max-seeds N` cap; the CLI truncates the list to the top N and re-numbers.
- Default (`--max-seeds 0`) is unchanged: all seeds are kept, now ordered
  best-first (previously peel order). Stage 2's own `--max-seeds` path is
  unaffected and already applied the same ordering.

The top-10 seeds on t1_sour are all 100%-forward, 0.18–0.39 level-consistency,
